# Shared-code retrospective after the volleyball MVP (ticket #80, epic #25)

Question: with football and volleyball both shipped, what is now duplicated across `src/games/football/` and `src/games/volleyball/`, and what should be shared?

Method: read both sports and the shared hosts at commit `cab0e8a` (master). Findings only: nothing is extracted in this ticket. Where a claim is about identical CSS, it was checked rule block by rule block, not by line counts.

## What #67 decided

Nothing is recorded. #67 closed as completed on 2026-10-19 with no comment, no linked PR and no research branch, and the epic says the build is "not blocked on #67: extraction is judged after the initial implementation". So this retrospective compares volleyball against the **audit's predictions** (#66, on `research/football-shared-code-audit`, which never had a PR) and against what actually landed in shared code since.

Shared since the audit, which volleyball reused: `BannerTiming` on `useBanner` (a per-sport hold time), per-sport board layouts in `BoardRegistry` (`?layout=`), the shared `Wordmark`, `HeaderSlot`/`InHeader` (top bar placement), `RollingNumber`, and sport-neutral discard wording in `MatchSession` (#82). Everything else the audit flagged was copied.

## Accidental coupling

- No cross-sport imports in either direction. The engine/board/console boundaries held, and the lint rules pass.
- No hardcoded sport lists or football copy in the shared hosts: the only mentions of football outside `src/games/football/` are the `builtin.ts` registrations and comments.
- `GameEngine.clockTiming` is football-shaped and sits on the shared contract in `src/engines/types.ts`, with `legacyEpochRunningSince` (a migration for football backups) on the neutral interface. It is optional and `ConsoleHost`, `BoardHost` and `MatchSession` handle its absence, so volleyball is unaffected; it matters only when the next sport arrives. Not worth a ticket yet.
- `storage.VERSION` is now 2 with a `LEGACY_VERSION` path, but still global to all sports. That was true at the audit and is still the epic's open "persistence" note.
- `DEFAULT_BANNER_TIMING` is football-tuned in a shared file, as the code comment says.

## Placement (the one architectural decision)

Neutral cross-sport types and helpers need a home. Two options:

- `src/games/shared/` (flat, no `board/` `engine/` `console/` subdirectories). The existing glob `src/games/*/*.{ts,tsx}` already matches it, so the neutral-seam rule applies with no lint change. Cost: `src/games/` stops meaning "one directory per sport" (README and the `src/games/<sport>/` wording would need a line).
- `src/shared/`. Clearer, but needs its own `no-restricted-imports` block.

Shared React lives beside what it serves: `src/consoles/` (console chrome, sheets, settings frame) and `src/boards/` (stage, banner frame). Both are currently unlinted, so each extraction ticket adds the rule at the same time.

## Decision: what to extract and in what order

1. **Team basics and validation guards** (new neutral home).
2. **Console chrome** (`useUndoHotkey`, `useToast`, `ConsoleTopBar`). Before #105 (reset), which would otherwise add a third copy of the top-bar wiring.
3. **Sheet pattern** (`SheetFrame`, `Keypad`, digit entry). Independent of the rest.
4. **Board stage** (`BoardStage`). Before #89 (minimal layout), which would be the third user.
5. **Banner frame**. After 4.
6. **Settings frame**. Last.

Not now: undo (blocked on #79, with these findings as input), notice ids, config validation, pips, team column. 2, 3 and 4 can run in parallel once 1 has landed.
